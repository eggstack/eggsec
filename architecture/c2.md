# C2 (Command & Control) Module

## Role & Responsibilities

Standalone defense-lab module for simulating C2 operations: beaconing, tasking, campaign orchestration, agent lifecycle, and OPSEC assessment. Provides realistic purple team exercises with MITRE ATT&CK campaign profiles (APT29, Carbanak, Generic). This is **simulation and defense validation**, not offensive tooling.

**Non-responsibilities**: Does not wire to MCP/TUI/pipeline surfaces (standalone defense-lab CLI only — `mod.rs:11`). Does not implement real implant protocols. Does not provide agent persistence or exfiltration primitives.

## Behavior / Flow

### Scan Lifecycle (`mod.rs:303-350`)

```
CLI args → handle_c2() → EnforcementContext → C2Scanner::new(dry_run, profile) → scan(target)
  ├─ dry_run  → dry_run_simulation()
  │    ├─ beacon::simulate_beacons(campaign, "dry-run", true)
  │    ├─ tasking::simulate_tasks(campaign, "dry-run", true)
  │    └─ opsec::simulate_opsec_assessment()  [always synthetic]
  └─ real     → real_simulation(target)
       ├─ beacon::simulate_beacons(campaign, target, false)  [real HTTP/S, DNS, TCP]
       ├─ tasking::simulate_tasks(campaign, target, false)   [real port scan, HTTP POST]
       └─ opsec::simulate_opsec_assessment()  [always synthetic]
```

1. **Construction**: `C2Scanner::new(dry_run, campaign_profile)` resolves the campaign from profile string
2. **Beacon simulation** (`beacon.rs`):
   - **Dry-run**: `dry_run_beacons()` — pure synthetic, one `BeaconResult` per campaign technique, all `success: true`, evidence prefixed "dry-run:"
   - **Real**: `real_beacons()` — HTTP/S via reqwest (10s timeout), DNS via `tokio::net::lookup_host()`, TCP via `tokio::net::TcpStream::connect()`. Failures produce `success: false` with error evidence. No panics.
3. **Task simulation** (`tasking.rs`):
   - **Dry-run**: `dry_run_tasks()` — synthetic per-technique results, all `Completed` or `Simulated`
   - **Real**: `real_tasks()` — TCP port scan (80, 443, 8443, 8080, 4443, 3s timeout each), HTTP POST task delivery (5s timeout), 1KB exfil payload, decoy HTTP traffic. Postex-enriched techniques use dry-run messaging (real postex primitives are out of scope). Persistence tasks always `Simulated` (evidence-only).
4. **OPSEC assessment** (`opsec.rs`): `simulate_opsec_assessment()` — always synthetic (6 findings, score = 100 - weighted deductions: High=20, Medium=10, Low=5, Info=0 → default score = 50)
5. **Attack graph + timeline** (`campaign.rs`): `build_attack_graph()` connects techniques across phases (phase N depends on phase N-1), `build_timeline()` generates sequential timestamps. Critical path = first technique per phase.
6. **Report**: `C2Report` with summary counts (beacons successful/total, tasks completed/total, OPSEC score/max)

### Beacon Jitter/Sleep Semantics (`beacon.rs:26-33`)

Default parameters per protocol:

| Protocol | Interval | Jitter |
|----------|----------|--------|
| HTTPS | 60,000 ms (60s) | 25% |
| DNS | 300,000 ms (5m) | 50% |
| TCP | 120,000 ms (2m) | 15% |
| HTTP | 300,000 ms (5m) | 30% |
| Custom | 600,000 ms (10m) | 75% |

These are **report values only** — the module does not implement actual sleep/jitter loops. The values appear in `BeaconResult.interval_ms` and `BeaconResult.jitter_percent` for reporting and analysis.

### Agent Lifecycle (`agent.rs:140-232`)

`simulate_agent_lifecycle()` runs a finite state machine:
1. **Registration**: `AgentInstance::new(config)` → `AgentState::Registered`
2. **Check-ins**: One per campaign phase → `AgentState::Active`, tasks generated per MITRE technique
3. **Self-destruct**: If `auto_self_destruct && checkin_count >= max_checkins` → `AgentState::SelfDestructed`
4. **Termination**: After campaign completion → `AgentState::Terminated`

`task_type_for_technique()` (`agent.rs:234-248`) maps MITRE IDs to `TaskType`:
- T1071/T1071.001/T1071.004/T1573/T1573.002 → Recon
- T1059/T1053 → Execute
- T1003/T1555 → Recon
- T1021.002/T1021.001/T1021.006 → Lateral
- T1041/T1570 → Exfil
- T1070.006 → Evade
- T1547.001 → Persist

## Safety Model

- **Dry-run default**: CLI defaults to dry-run; real requires explicit `--allow-c2`
- **Policy enforcement**: `EnforcementContext::evaluate()` runs before any execution
- **Standalone defense-lab**: `mod.rs:11` declares "No MCP/agent/TUI/pipeline integration" — the module is deliberately isolated
- **Real network I/O bounded**: All real operations have timeouts (10s beacons, 5s tasks, 3s port scans)
- **No panics**: All errors caught and converted to `success: false` / `TaskStatus::Failed` with evidence
- **OPSEC always synthetic**: Even in real mode, `opsec::simulate_opsec_assessment()` returns static findings (defense recommendations, not attack primitives)
- **Postex enrichment uses dry-run messaging**: Real tasking (`tasking.rs:406-414`) wraps postex techniques with "dry-run:" prefixed output — real postex execution is out of scope for the C2 module
- **Persistence always simulated**: `real_persist_task()` (`tasking.rs:384-395`) returns `TaskStatus::Simulated` with evidence-only output

## Invariants & Gotchas

1. **No MCP/TUI/pipeline integration**: `mod.rs:11` explicitly declares standalone defense-lab — C2 is not wired to automated surfaces
2. **`c2-mcp` always dry-run**: Even with MCP feature, real C2 is impossible via MCP
3. **Real postex out of scope**: `tasking.rs:406` comment + implementation shows postex enrichment always uses dry-run messaging in real mode
4. **Persistence always simulated**: `real_persist_task()` returns `Simulated` status regardless of mode (`tasking.rs:384`)
5. **OPSEC always synthetic**: `simulate_opsec_assessment()` is called identically in both dry and real paths (`mod.rs:355-356`, `366-367`)
6. **Beacon jitter is reporting-only**: No actual sleep/timing — values are `BeaconResult` fields for analysis
7. **Default campaign fallback**: Any unknown profile string resolves to `Generic APT` (`mod.rs:278`)
8. **Real beacons use 10s timeout**: `beacon.rs:77` — may be slow for multiple phases
9. **Real tasks use 3s port scan timeout**: `tasking.rs:184` — 5 ports × 3s = 15s worst case per recon task
10. **57 tests**: All pass; real-mode tests target unreachable hosts (127.0.0.1:1) to verify failure paths
