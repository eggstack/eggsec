## How Regeneration Works

The checked-in `.rs` file header (`eggsec.tool.v1.rs:1-15`) states:

> **CANONICAL GENERATED FILE**: This file is checked into source control and
> compiled directly. Builds do NOT require protoc or prost-build for the
> Rust code (protoc is only needed for tonic-reflection descriptor set).

**Regeneration workflow** (maintainer task):
1. Install protoc (e.g., `apt install protobuf-compiler`)
2. `cargo build --features grpc-api`
3. `cp target/debug/build/eggsec-*/out/eggsec.tool.v1.rs crates/eggsec/src/generated/eggsec.tool.v1.rs`

**Why checked in**:
- Builds do NOT require `protoc` for normal Rust compilation — only `prost-build` + `protoc` for the descriptor set
- The descriptor set (`tool_descriptor.bin`) is generated at build time by `build.rs` and used for `tonic-reflection` service discovery
- The checked-in Rust file enables `cargo build` without protoc installed (common in CI and contributor environments)

**What `build.rs` does** (`build.rs:1-29`):
```rust
#[cfg(feature = "grpc-api")]
{
    // Generates file descriptor set for tonic-reflection
    prost_config.file_descriptor_set_path(&descriptor_path);
    prost_config.compile_protos(&["src/tool/protocol/grpc.proto"], &["src/tool/protocol/"])
}
```
Only generates the `.bin` descriptor file — the Rust code is never regenerated by `build.rs`. The `prost-build` dependency is optional and only pulled in with `grpc-api`.

## Streaming Protocol (`StreamExecuteTool`)

`StreamExecuteTool` uses server-side streaming. Each message is a `ToolStreamEvent` (`:67`) containing a `request_id` and one of four event variants:

| Variant | Type | Fields | Description |
|---------|------|--------|-------------|
| `Progress` | `ProgressEvent` | `message: String`, `percent: u32` | Progress update (0-100) |
| `Finding` | `FindingEvent` | `finding: Option<Finding>` | Incremental finding |
| `Complete` | `CompleteEvent` | `response: Option<ExecuteToolResponse>` | Terminal: final results |
| `Error` | `ErrorEvent` | `message: String`, `code: String` | Terminal: failure |

The stream ends after `CompleteEvent` or `ErrorEvent`. Clients must not expect further messages after either terminal event.

```
Client                     Server
  |--- ExecuteToolRequest -->|
  |<-- ProgressEvent --------|  (0%)
  |<-- FindingEvent ---------|  (finding #1)
  |<-- ProgressEvent --------|  (45%)
  |<-- FindingEvent ---------|  (finding #2)
  |<-- ProgressEvent --------|  (100%)
  |<-- CompleteEvent --------|  (terminal)
```

## Invariants & Gotchas

1. **Do not edit the generated file**: Changes to `eggsec.tool.v1.rs` are overwritten on regeneration. Edit `grpc.proto` instead.
2. **protoc is not needed for builds**: Only needed for regeneration (maintainer task) and tonic-reflection descriptor generation (build.rs).
3. **`RequestOptions.headers` uses `std::collections::HashMap`**: Unlike the engine's preferred `FxHashMap`, protobuf-generated code uses `std::collections::HashMap`. This is forced by prost's code generation.
4. **`Finding.severity` is a `String`**: Not an enum. The engine's `Severity` enum (in `eggsec-core`) maps to/from this string at the boundary.
5. **Max decode size**: Default 4 MB for client, `usize::MAX` for server. Both are configurable.
